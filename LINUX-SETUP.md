# Linux setup (this machine)

Arm Studio is installed as a packaged AppImage, extracted to a fixed directory
that the desktop launcher points at. Rebuilding and reinstalling replaces that
directory, so the launcher always runs the newest build.

## Installed locations

| What | Path |
|---|---|
| App (extracted AppImage) | `~/Applications/ArmStudio` |
| Launcher command | `~/bin/arm-studio` (already on `PATH`) |
| Menu entry | `~/.local/share/applications/ArmStudio.desktop` |
| Icon | `~/.local/share/icons/hicolor/512x512/apps/arm-studio.png` |

Launch from the app menu or with `arm-studio`.

The app icon is a placeholder from SVGRepo (`electron/electron-builder/icon.svg`),
rendered to `icon.png` and `icon.ico`.

## Build and install the newest build

```bash
./release.sh
```

This publishes the PlotterHelper engine, builds the web and server bundles,
packages `Arm Studio` as a Linux AppImage with electron-builder, then extracts
the newest AppImage over `~/Applications/ArmStudio` and refreshes the launcher,
menu entry and icon. Older AppImages are pruned. Run it again after any change
and the launcher picks up the new build.

## Develop with live rebuilds

```bash
./dev.sh
```

Builds once, starts `webpack --watch` for both the web and server bundles, and
runs the app straight from the working tree (via `electron/`). Save a source
file and relaunch the app to see the rebuild.

## PlotterHelper engine

The Write & Draw toolpath engine is the .NET tool from the sibling
`Drawing-Extension` checkout, published self-contained so the app needs no .NET
runtime:

```bash
scripts/build-plotter-helper.sh
```

Overrides: `PLOTTER_HELPER_SRC` (default `../Drawing-Extension`),
`PLOTTER_HELPER_SELF_CONTAINED` (default `true`), `PLOTTER_HELPER_RID`
(default `linux-x64`). If the engine is missing the server falls back to its
built-in SVG converter.

## Local build notes

- The web bundle's i18n assets and `build-web/index.html` are generated by the
  machine-local `local/web-build/build.sh` wrapper (see `local/README.md`).
  `release.sh` calls it with `NODE_PATH` pointing at `web/node_modules`, since
  the helper scripts now live outside `web/`.
- electron-builder packs the server's runtime dependencies from
  `electron/package.json`; `serialport` uses N-API prebuilds, so no native
  rebuild is needed (`npmRebuild: false`).

## Linux portability fixes

- `server/CuraEngine/Config` renamed to `CuraEngine/config`; the code and
  `.gitignore` already used the lowercase name, which case-insensitive
  filesystems hid.
- `web/src/containers/basic/index.jsx` renamed to `Index.jsx` to match the
  import; the old name only worked on case-insensitive filesystems.
- `plotterHelperBridge.js` picks `PlotterHelper` on Linux/macOS and
  `PlotterHelper.exe` on Windows.

## CuraEngine

The 3D print module shells out to CuraEngine 5.13.0, bundled under
`server/CuraEngine/5.13.0/`:

- `Linux-x64/` and `Win-x64/` are present. The Linux build came out of Cura's
  AppImage, so it is patched to use the system loader
  (`/lib64/ld-linux-x86-64.so.2`) with `RPATH=$ORIGIN`, and the libs it needs
  (`libArcus`, `libpolyclipping`, `libssl`/`libcrypto` 3.2, `libtbb`) sit next
  to it.
- `server/CuraEngine/config/` is generated from Cura 5.13's definitions with
  the DexArm values applied. To regenerate after an engine bump:
  `local/cura-migration/gen-config.py <cura-definitions-dir> server/CuraEngine/config`.
- No macOS binary is bundled. Extracting it from a Cura `.dmg` works, but the
  dylib paths need verifying on a Mac.

The engine skips a setting's own value when it has children, so
`p3dStartSlice.js` passes `--force-read-parent`; without it, settings like
`min_wall_line_width` have no value and the slice crashes.

CuraEngine 5.x logs to stdout (4.6.2 logged to stderr), so `p3dStartSlice.js`
parses both streams to pick up layer progress, filament and print time.
